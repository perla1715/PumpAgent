SCHEMA AND IDENTITY

Schema: coinalyze-raw-evidence/v1. The caller supplies every required provenance
field and bytes explicitly. V1 accepts single-symbol GET history captures, with
closed metadata fields and a request-parameter allowlist. Optional provider API
version and content type require exactly a value or an unavailable reason.
Transport provenance requires an HTTP status or an explicit transport error.

The implementation adds required capture_status and quality_flags fields to make
the prompt's explicit status/quality requirements concrete. Statuses are
VALID_RESPONSE, MALFORMED_RESPONSE, INCOMPLETE_CAPTURE and PROVIDER_ERROR.
COMPLETENESS_NOT_ASSERTED is mandatory for every capture. Known gaps, duplicate
and conflicting records, empty histories, explicit open/incomplete candles and
null metrics require the corresponding quality flags. No repaired market-data
object is produced; inspection only validates identity and required markers.

Envelope timestamps must be timezone-aware ISO-8601 with at most microsecond
precision. They canonicalize to UTC and must satisfy request <= response <=
recorded. No file mtime or missing provider timestamp is substituted.

Identity covers provider, endpoint, HTTP method, canonical request parameters,
market, exchange, contract, symbol, interval and request start. raw_evidence_id
is re1: plus the SHA-256 of canonical request identity. Raw digest and size are
computed from the actual supplied bytes. A changed request start creates a new
capture identity; changed bytes or provenance under an existing identity cause
IDENTITY_CONFLICT. Exact repeat captures return DUPLICATE_NOOP without writes.

Metadata is deterministic UTF-8 JSON, with sorted keys, compact separators and a
trailing newline. Raw bytes are never re-encoded. The envelope includes all
provenance, identity, raw hash/size, relative raw/metadata references and manifest
sequence. metadata_digest hashes the complete metadata object and lives in the
manifest and returned result, avoiding a self-referential metadata digest.

PERSISTENCE AND REPLAY

Each capture is one ordered, 20-digit directory containing raw.bin,
metadata.json and manifest.json. Ordered manifest entries form an append-only
SHA-256 chain. There is no mutable index or separately rewritten manifest head.

An existing dedicated root is required. A writer locks the root directory,
creates an exclusive pending directory, fsyncs its root entry, writes/fsyncs
the three objects, fsyncs the pending directory, atomically renames the complete
bundle to its sequence name, then fsyncs the root. Committed objects are never
opened for writing. Cooperating concurrent writers serialize on the root lock.

Pre-publication failures leave explicitly reported pending entries. No pending
entry is automatically promoted, repaired or deleted. Pending entries block
new appends; exact committed duplicates still return DUPLICATE_NOOP with pending
names. A post-rename root-fsync failure returns PERSISTENCE_ERROR, not a success
claim. Replay determines whether the full bundle is committed before retry.

Replay revalidates every committed bundle, canonical metadata, recomputed
identity, raw hash/size, metadata digest, relative references, sequence order,
unique identity and manifest chain. Missing objects, symlinks, nonregular files,
invalid envelopes and mismatches return CORRUPTION_ERROR with no valid prefix.
Unknown root entries are reported without following or deleting them.

Structured archive results: ARCHIVED, DUPLICATE_NOOP, IDENTITY_CONFLICT,
VALIDATION_ERROR, PERSISTENCE_ERROR, CORRUPTION_ERROR.
Replay returns exact bytes in manifest order, pending names and an optional
error_status. Its complete flag describes archive recovery, never market-data
completeness. Supplied sensitive values are not echoed in error results.

DEVIATIONS, INTERPRETATIONS AND LIMITATIONS

No protected-scope deviation. The status/quality fields, exact optional-value
objects, single-symbol history scope and allowed parameter types make the
prompt's prose requirements concrete; README.md documents the complete API.
No separate acquisition or provider schema expansion is included.

The append-only manifest is one immutable entry per atomically published bundle,
not a mutable shared JSONL file. Manifest sequence/reference determinism depends
on append order, while request identity does not depend on archive location.

Filesystem semantics are local POSIX locking, rename and fsync. Fault injection
does not prove physical power-loss behavior. Network filesystems, distributed
writers and object stores are not supported by this contract. Root ancestors
and the local account are trusted. Immutability is enforced by the API, not
hardware or signatures. Coordinated malicious replacement of every object/hash,
or deletion of the complete archive/trailing bundles, needs an external trusted
anchor to detect. Replay currently scans and loads the entire archive in memory.

Validation does not establish provider truth, complete requested coverage or
implicit candle closure. Unsupported request metadata is rejected. Recognizable
secrets are rejected, but arbitrary opaque strings cannot be universally
identified as credentials; callers must supply credential-free inputs. The
archive never contacts a provider to verify, fill or replace missing evidence.
